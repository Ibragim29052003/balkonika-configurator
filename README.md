# Балконика · Личная студия интерьера

Интерактивный конструктор балкона на **React, TypeScript, Redux Toolkit и Three.js**. Подбор отделки, независимые шторы на двух сторонах, ковёр и освещение в собственной 3D-сцене.

[Демо без регистрации](https://ibragim29052003.github.io/balkonika-configurator/) · [Проверки](TESTING.md)

## Возможности

Настройки разделены на три вкладки: **«Отделка»** — стены и пол, **«Текстиль»** — шторы и ковёр, **«Свет»** — день/вечер и светильник. Каждая вкладка открывается нажатием.

- Три цвета стен × три покрытия пола; выбор и текстовая подпись обновляются сразу.
- Шторы на всём левом остеклении и дальнем окне: отдельные настройки, открытие, цвет ткани, длина 120–260 см, применение ко всем окнам.
- Необязательный ковёр с тремя цветами.
- День и вечер; подвесной светильник, выключатель, температура и яркость.
- Светлая и тёмная темы интерфейса с сохранением предпочтения.
- Три ракурса и ограниченный обзор мышью; на телефоне — кнопки ракурсов и прокрутка настроек.
- Общий сброс комнаты; тема интерфейса сохраняется.
- Упрощённая SVG-визуализация, если WebGL недоступен.

## Запуск

Нужен Node.js **22.12+** и npm. Версии зависимостей зафиксированы в `package-lock.json`.

```sh
npm ci
npm run dev
```

Открыть `http://127.0.0.1:4173`. Для принудительной проверки резервного режима: `http://127.0.0.1:4173/?mode=2d`.

```sh
npm run check        # строгая проверка TypeScript
npm test             # 29 тестов состояния и React-компонентов
npm run format:check # единое форматирование
npm run build        # production-сборка в dist/
npm run preview      # локальный просмотр production-сборки
```

GitHub Actions выполняет эти проверки при push в `main` и в pull request. После успешных проверок `main` автоматически публикуется на GitHub Pages. Для статического хостинга нужен только результат сборки `dist/`; сервер приложения, ключи API и переменные окружения не требуются.

## Архитектура

| Часть                                 | Ответственность                                                                  |
| ------------------------------------- | -------------------------------------------------------------------------------- |
| `src/components/`                     | Типизированные React-компоненты настроек, превью и доступного кастомного селекта |
| `src/store/roomSlice.ts`              | Все изменения комнаты: материалы, шторы, свет, ковёр и полный сброс              |
| `src/store/hooks.ts`                  | Типизированные `useAppDispatch` и `useAppSelector`                               |
| `src/state.ts`, `src/materials.ts`    | Начальные значения, палитры, подписи, размеры штор и параметры света             |
| `src/scene.ts`                        | Геометрия, материалы, камера, источники света и освобождение ресурсов Three.js   |
| `src/textures.ts`                     | Детерминированные текстуры дерева, камня, ткани и картины через Canvas           |
| `src/fallback.ts`, `src/fallback.svg` | Резервная 2D-сцена с тем же контрактом `RoomRenderer`                            |
| `src/hooks/useTheme.ts`               | Тема, системное предпочтение, localStorage и синхронизация между вкладками       |
| `tests/`                              | Проверки Redux и поведения настоящей React-формы в jsdom                         |

Поток изменения: **действие пользователя → типизированный action → roomSlice → форма и `SceneViewport` → обновление сцены**. В Redux хранятся только сериализуемые настройки. Объекты Three.js, DOM, камера и подписки находятся за границей store.

Redux Toolkit хранит общее состояние панелей настроек и визуализатора; reducer проверяется отдельно. Локальные вкладки, ракурс и тема остаются в React. RTK Query не подключён: сетевых данных нет.

`SceneViewport` загружает Three.js отдельным чанком и создаёт визуализатор в эффекте. При размонтировании удаляются наблюдатели, управление камерой, геометрии, материалы и текстуры. Отрисовка происходит при изменении параметров, размера или камеры, без постоянного цикла анимации. Учтён повторный запуск эффектов в React StrictMode. В UI используются обычные HTML/CSS и React; WebGL отвечает за интерьер.

## Визуальное решение

Модель балкона и материалы созданы в коде без внешних изображений, CDN, шрифтов и платных сервисов. Окна — отдельные проёмы и элементы геометрии: перекраска стен и пола не затрагивает их. Справа расположена скамья с цельным основанием, у столика одна центральная опора. Шторы охватывают обе группы окон.

Дневной источник света создаёт тени, вечером он выключается, а светильник освещает поверхности локально. Цветовые фильтры поверх 3D-сцены и туман не используются. Это стилизованная визуализация, а не фотосъёмка или инженерный расчёт освещённости. Значения температуры света служат визуальными пресетами. Резервный SVG-режим упрощает перспективу и освещение; свободного обзора в нём нет.

## Доступность и ограничения

Нативные radio, checkbox и range, подписи полей, видимый фокус, live region выбранной отделки и вкладки с клавиатурным управлением. Кастомный select поддерживает стрелки, Home/End, Enter, Escape, Tab и поиск по началу подписи. Его меню выводится через portal с позиционированием в пределах экрана. Учитывается `prefers-reduced-motion`.

Тема хранится локально; конфигурация комнаты сбрасывается при перезагрузке. Цены, регистрация, заявки, CRM, сервер и сохранение проектов в аккаунте отсутствуют. Размеры модели условные; реальные цвета и размеры материалов могут отличаться. Полная матрица браузеров и физические телефоны не проверялись.

## Небольшие правки

- Палитры и исходная отделка: `src/materials.ts`.
- Исходная комната, ткань, ковёр и пресеты света: `src/state.ts`.
- Геометрия, мебель и ракурсы: `src/scene.ts`.
- Тема и адаптивная компоновка: `src/styles.css`.

После изменения начальных параметров достаточно обновить фабрику `createInitialState`: Redux и контролируемая React-форма используют один источник значений. Для нового параметра комнаты нужно добавить тип, reducer, поле управления и обновление визуализатора, затем проверить независимость настроек и общий сброс.

Workflow `.github/workflows/check.yml` разделяет проверку/сборку и публикацию; pull request не разворачивается в production. У deploy-job есть только необходимые права Pages и OIDC. Относительный `base` Vite позволяет размещать сборку и в подкаталоге репозитория, и в корне домена. Настройка основана на [документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) и [Vite](https://vite.dev/guide/static-deploy.html#github-pages).
